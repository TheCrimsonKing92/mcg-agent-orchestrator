# Process-spawning lane cost diagnosis

## Scope and confidence

This is a source inspection only. I did not run the test suite, a lane, or a timing probe. The duration values in the request are therefore **input measurements**, not facts independently verified from the repository. Claims below are tagged **Fact** when the cited source directly establishes them, **Inference** when the source supports but does not prove the conclusion, and **Not verified** when the repository does not contain the discriminating evidence.

The lane really is the seven named classes, and the checked-in test asserts that exact membership and the lane's exact key (`tests/Mcg.AgentOrchestrator.Infrastructure.Tests/ProcessSpawningCollectionSplitTests.cs:23-31`, `tests/Mcg.AgentOrchestrator.Infrastructure.Tests/ProcessSpawningCollectionSplitTests.cs:57-67`). The manifest supplies the same seven-class filter and the only current `xunit:ProcessSpawning` declaration (`config/acceptance-manifest.json:65-68`).

## Executive conclusions

1. **Fact:** only a minority of the assertions require real process behavior. `ConductorSuccessorSelfCheckTests` requires no child process at all (`tests/Mcg.AgentOrchestrator.Infrastructure.Tests/ConductorSuccessorSelfCheckTests.cs:7-53`); two of five `ConductorSelfRelaunchTests` are already injected seam tests (`tests/Mcg.AgentOrchestrator.Infrastructure.Tests/ConductorSelfRelaunchTests.cs:74-150`); two of three `ProcessTreeGuiSuppressionTests` only inspect source (`tests/Mcg.AgentOrchestrator.Infrastructure.Tests/ProcessTreeGuiSuppressionTests.cs:111-148`); and substantial portions of `DispatchProcessHostTests`, `LauncherScriptTests`, and `MtpTestRunnerScriptTests` assert data transformation, failure classification, generated command structure, or source wiring rather than process semantics (method-by-method classification below).
2. **Fact:** the current manifest key does not serialize this lane against any other current lane, because the scheduler blocks only a shard whose key is in the active-key set and no other current lane declares `xunit:ProcessSpawning` (`src/Mcg.AgentOrchestrator.Infrastructure/Workspaces/GoalAcceptanceVerifier.cs:1241-1246`, `src/Mcg.AgentOrchestrator.Infrastructure/Workspaces/GoalAcceptanceVerifier.cs:1279-1306`, `config/acceptance-manifest.json:65-73`). **Inference:** deleting only the key would save zero seconds in the current manifest.
3. **Fact:** the seven classes are serial inside their MTP process because their xUnit collection has `DisableParallelization = true`; the fixture also mutates the process environment for the collection lifetime (`tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyInfo.cs:32-35`, `tests/Mcg.AgentOrchestrator.Infrastructure.Tests/TestCollections.cs:11-25`, `tests/Mcg.AgentOrchestrator.Infrastructure.Tests/TestCollections.cs:85-98`). The repository's own isolation note says the manifest key is only an admission constraint inside one verifier and cannot coordinate simultaneous gates (`docs/acceptance-gate-resource-isolation.md:3-14`).
4. **Fact:** source does not establish an all-pairs conflict among the seven classes. The strongest verified cross-class, same-process collision is `ProcessTreeGuiSuppressionTests` versus process-starting `DispatchProcessHostTests`: production temporarily changes the process-global Windows error mode under a lock, while the test reads the mode outside that lock before and after its launch (`src/Mcg.AgentOrchestrator.Infrastructure/Processes/ProcessTreeGuiSuppression.cs:79-105`, `tests/Mcg.AgentOrchestrator.Infrastructure.Tests/ProcessTreeGuiSuppressionTests.cs:77-91`, `src/Mcg.AgentOrchestrator.Infrastructure/Processes/DispatchProcessHost.cs:1444`). Other concrete hazards found are chiefly within one class, against another gate, or against an external operator, not pairwise among all seven (details below).
5. **Inference, strong but not verified:** the approximately 119-second floor is most plausibly the Infrastructure apphost's module initializer trying to apply a Low integrity label. Every lane starts the same Infrastructure test executable with a filter (`config/acceptance-manifest.json:172-188`, `src/Mcg.AgentOrchestrator.Infrastructure/Workspaces/GoalAcceptanceVerifier.cs:6453-6492`); its module initializer prepares a new PID-named temp root before any test runs (`tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyTempRedirect.cs:16-48`, `tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyTempRedirect.cs:350-370`); and a missing/inadequate label causes `icacls /setintegritylevel` to wait up to exactly two minutes (`tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyTempRedirect.cs:314-330`, `src/Mcg.AgentOrchestrator.Infrastructure/Processes/WorkerSandboxPreparer.cs:544-574`, `src/Mcg.AgentOrchestrator.Infrastructure/Processes/DispatchProcessHost.cs:1014-1023`). A controlled negative control or retained per-process diagnostic correlated with lane timing was not inspected, so causality remains **not verified**.

## 4. The approximately 119-second floor

### Source trace

1. Every Infrastructure lane resolves the same Infrastructure test project/executable and appends only lane-specific filter arguments (`config/acceptance-manifest.json:172-188`, `src/Mcg.AgentOrchestrator.Infrastructure/Workspaces/GoalAcceptanceVerifier.cs:6453-6492`).
2. Before tests run, a module initializer creates a physical filesystem and real `IcaclsIntegrityLabeler`, selects a writable temp root, and redirects process `TMP`/`TEMP` (`tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyTempRedirect.cs:16-48`).
3. Its first Windows candidate is a new PID-named directory under `LOCALAPPDATA/Temp/Low/mcg-tests` and requires a Low inheritable label (`tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyTempRedirect.cs:350-370`).
4. Preparation queries the label; if it is absent/inadequate, it calls `SetIntegrity`, then queries again (`tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyTempRedirect.cs:242-245`, `tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyTempRedirect.cs:314-330`).
5. `Query` starts `icacls`, redirects both streams, and permits a 30-second wait after reading them (`src/Mcg.AgentOrchestrator.Infrastructure/Processes/WorkerSandboxPreparer.cs:476-513`). `SetIntegrity` starts `icacls /setintegritylevel`, drains both streams, and passes a two-minute timeout to `WaitForIntegrityLabeler` (`src/Mcg.AgentOrchestrator.Infrastructure/Processes/WorkerSandboxPreparer.cs:544-574`). The wait kills only after that timeout (`src/Mcg.AgentOrchestrator.Infrastructure/Processes/DispatchProcessHost.cs:1014-1023`).
6. If the Low candidate is rejected, selection can fall back to a PID-named directory beside the test executable that does not require a Low label (`tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyTempRedirect.cs:207-223`, `tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyTempRedirect.cs:368-370`). Thus a timed-out Low-label attempt can add almost exactly two minutes and still let the lane proceed.

**Inference:** that path accounts for a content-independent ~119-second floor much better than any of the seven lane classes, because it executes once in every filtered test-host process before discovery and contains an explicit 120-second wait. **Not verified:** whether the recorded 71 processes actually entered `SetIntegrity`, whether `icacls` timed out rather than completed, and whether a second common startup path contributed. The initializer also reaps orphan roots by taking a process-table snapshot; its source records an earlier 53.5-second case with 1,106 roots, reduced to 3.1 seconds after cleanup (`tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyTempRedirect.cs:140-189`). That can add startup cost, but it does not by itself explain a stable 119-second floor.

The manifest passes `--long-running 120` to the MTP executable (`config/acceptance-manifest.json:175-188`). **Not verified from repository source:** the implementation of that third-party switch is not present here, so this inspection cannot prove or exclude it as a cause. The local source does prove the independent two-minute `icacls` path above.

### Minimal proof required before changing the startup path

Add startup phase receipts around candidate creation, first query, `SetIntegrity`, second query, orphan sweep, and module-initializer completion, including elapsed time and the selected/rejected diagnostic. Those are the exact branch points in `AssemblyTempRedirect.Install`, `TryPrepareRoot`, and `EnsureLowLabel` (`tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyTempRedirect.cs:16-48`, `tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyTempRedirect.cs:226-336`). Then run one tiny filtered lane once with the current implementation and once with a pre-established Low-inheritable parent. This is the controlled comparison needed to turn the inference into a cause; it is **not performed here**.

Any fix must preserve the existing negative controls: selected root is Low where required, a child directory/file is writable, cleanup succeeds, and failure falls back rather than poisoning test discovery (`tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyTempRedirect.cs:4-6`, `tests/Mcg.AgentOrchestrator.Infrastructure.Tests/AssemblyTempRedirect.cs:226-304`). A likely low-risk design is to establish and verify one stable Low-inheritable parent once, then create unique PID children that inherit it; whether inheritance behaves correctly on this host is **not verified**.
