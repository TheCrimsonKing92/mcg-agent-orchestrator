# Test audit 79a59101

The measured order and means come from `79a59101-measurements.md`. This pass keeps every
test in `xunit:GoalWorktreeCleanupHooks`; lane membership and the manifest estimate are
therefore unchanged. The executed reduction replaces four repeated full state migrations with
copies of one process-local, current-schema empty-state template. Each test still creates its
own repository, Git history, worktrees, state stores, and cohort artifacts.

## RetryableLandingHold_PreservesPassingReceipt_AndLaterRelandsIdenticalState

- **Measurement:** 69 runs, 16.29 s mean.
- **Claim:** a passing receipt held by an operator-controlled landing pause remains valid and is
  reused to land the identical cohort state after the pause clears, without another gate run.
- **Asserted boundary and precondition:** two completed goal branches and their combined tree are
  projected before a passing receipt is stored; the first run is held and the second run uses
  the same selection. Assertions retain receipt validity, held/executed outcomes, unchanged then
  combined `main`, zero verifier runs, exact branch revisions, and cohort-workspace cleanup.
- **Expensive region:** after entry, generic repository setup performs a complete state migration;
  the test then creates two real Git worktrees and commits, materializes the combined workspace,
  persists a receipt, and runs both held and resumed landing paths before final cleanup.
- **Deletion consequence:** landing retries could rerun a paid gate, lose authoritative evidence,
  land a different tree, mutate goal branches, or leave cohort workspaces behind.
- **Duplicate/decomposition analysis:** other cohort tests cover ordinary landing or invalid cached
  evidence, but none crosses the held-to-resumed transition with the identical stored receipt.
- **Disposition: reduce subject (executed).** Use the reduced repository factory. The database is
  still an isolated exact-schema empty state store; only its repeated migration is removed. The
  real Git/cohort operations and every assertion remain unchanged.

## ProductionRed_OneFailedMember_RequeuesGreenPeer

- **Measurement:** 69 runs, 11.25 s mean.
- **Claim:** after a combined RED, one failing partition and one passing partition are attributed
  to the first member, while the innocent peer receives exactly one idempotent overtake credit.
- **Asserted boundary and precondition:** two completed candidates are projected and the verifier
  returns combined-fail, first-fail, second-pass. Assertions retain invocation order, attribution,
  held outcomes, unchanged `main`, per-member overtake counts, and idempotent side effects.
- **Expensive region:** generic repository setup performs a full state migration before two real
  candidate worktrees/commits, combined materialization, three partition decisions, persistence,
  attribution, and cleanup.
- **Deletion consequence:** the conductor could blame or penalize the green peer, fail to requeue
  it, double-apply fairness credit, or mutate `main` after a RED.
- **Duplicate/decomposition analysis:** the interaction-only test owns the both-green partition
  classification; it does not prove asymmetric failure attribution or the peer's idempotent credit.
- **Disposition: reduce subject (executed).** Use the reduced repository factory while preserving
  the real Git candidates, production cohort path, verifier sequence, stores, and all assertions.

## ProductionBatch_SelectsRunsPersistsLandsAndCleansOneSharedCohort

- **Measurement:** 69 runs, 10.62 s mean.
- **Claim:** one production batch selects two ready goals, runs one shared acceptance gate with a
  stable-slot lease, persists its evidence, lands both changes, resets fairness, and cleans the
  shared cohort workspace.
- **Asserted boundary and precondition:** two completed candidate worktrees and a passing TRX feed
  one permissive batch iteration. Assertions retain the single gate run, observed lease, fairness
  reset, two advances, both landed files, no cohort workspaces, and persisted exit/TRX evidence.
- **Expensive region:** a full state migration precedes two real worktree commits; the bounded batch
  iteration then performs selection, materialization, gate orchestration, persistence, landing,
  cleanup, and SQLite verification.
- **Deletion consequence:** the production batch could run duplicate gates, omit the trusted lease
  or evidence, partially land a cohort, retain fairness debt, or leak its workspace.
- **Duplicate/decomposition analysis:** lower-level selection, store, and landing tests do not own
  the single production-batch path joining all of these seams.
- **Disposition: reduce subject (executed).** Use the reduced repository factory. The batch and all
  real cohort artifacts remain the subject; repeated schema migration, which is not asserted, does
  not.

## ProductionRed_RunsBothPartitions_AndClassifiesInteraction

- **Measurement:** 69 runs, 10.20 s mean.
- **Claim:** when the combined cohort is RED but both member partitions are GREEN, the conductor
  classifies an interaction-only failure, holds both members, suppresses that exact pair, and
  persists both partition receipts without moving `main`.
- **Asserted boundary and precondition:** two completed candidates feed a combined-fail,
  first-pass, second-pass verifier sequence. Assertions retain all three invocations and goal IDs,
  failure/interaction attribution, held outcomes, unchanged `main`, workspace cleanup, pair
  suppression, and two persisted partition receipts.
- **Expensive region:** repeated full state migration occurs before two real worktree commits,
  combined materialization, three verification decisions, attribution persistence, and cleanup.
- **Deletion consequence:** interaction failures could be misattributed to a member, rerun as the
  same bad pair, omit partition evidence, mutate `main`, or leak the cohort workspace.
- **Duplicate/decomposition analysis:** the asymmetric-failure test proves member attribution, not
  the distinct interaction-only classification and pair-suppression contract.
- **Disposition: reduce subject (executed).** Use the reduced repository factory; retain the same
  production path, repositories, verifier sequence, persistence, cleanup, and assertion set.

## Reduction boundary

`CreateReducedAcceptanceCohortRepository` creates the same short-root real Git seed used by the
class and writes a byte copy of a lazily created migrated empty database into each repository.
Template creation closes migration connections, verifies `StateDbMigrations.IsUpToDate`, and
then reads immutable bytes. Tests share no connection, WAL file, journal, database handle, or
mutable store. A template creation, verification, read, or per-test copy failure is loud.
