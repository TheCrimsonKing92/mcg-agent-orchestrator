# Negative-control receipt: immutable state-outbox lease migration

## RED

Executed before the implementation on 2026-08-10 against an isolated WAL fixture. The fixture
recorded migrations 1 through 7 and created `state_outbox` without
`processing_started_at`. The named check `Version7OutboxBeforeMigration` queried that column.

Result: `migration_count=7`, then
`no such column: processing_started_at`, exit 1. No live orchestrator store was read or changed.

The checked-in behavioral control is
`Version7OutboxMigrationAddsLeaseColumnsAndDrainsExactlyOnce`. Its genuine v7 fixture retains
exactly migration rows 1 through 7 and the four legacy outbox columns. Before authorized migration,
the repository claim must throw `no such column: quarantined_at` and must not invoke delivery.

## GREEN

Executed after the implementation on 2026-08-10 with the app assembly produced by the sanctioned
worker build. The product-level smoke bootstrapped an isolated scratch store, rewrote only that copy
to the four-column v7 fixture, and ran an ordinary `goals` read. The read exited 0 and inspection
remained `7:id,kind,payload_json,created_at`, proving the no-authority path did not mutate it.

The same isolated store was then opened through the existing backlog-intake migration-authority
path. Although the no-match intake command itself exited 1, startup completed migration first;
inspection returned
`8:state-outbox-lease-columns:id,kind,payload_json,created_at,quarantined_at,quarantine_reason,processing_token,processing_started_at`.
A second authorized startup retained `8` total migrations, exactly one migration-8 row, and exactly
one `ix_state_outbox_kind` index. The isolated fixture was removed afterward.

The implementation makes that same fixture stale (`IsUpToDate == false`), applies immutable
migration 8 through explicit authority, and asserts all of the following in the named focused tests:

- the exact four lease/quarantine columns and `ix_state_outbox_kind` are present;
- migration 8 is recorded once and a second migration run is harmless;
- one claimant completes and removes the queued receipt, while a second attempt does nothing;
- successor preflight admits v7, an ordinary CLI read leaves it at v7, and conductor authority
  upgrades it;
- a persisted goal-creation receipt fails on the v7 schema, then delivers without duplicate side
  effects after the authorized migration, and a second retry reports `alreadydelivered`.

Developer .NET execution is intentionally limited to the sanctioned compile check plus the
product-level smoke above. The exactly-once delivery GREEN requires the acceptance-owned focused
filters for
`Version7Outbox|SuccessorPreflightAllowsOutboxQuarantineColumnMigration`,
`PersistentRunnerGoalCreateDeliveryFailureIsDurableAndRetryOnly`, and
`StateDbStartupMigrationsRequireConductorAuthorityOrExplicitBacklogBootstrap`. The acceptance receipt
must record non-zero matched tests and pass before this control is complete; compilation alone is not
a behavioral GREEN.
