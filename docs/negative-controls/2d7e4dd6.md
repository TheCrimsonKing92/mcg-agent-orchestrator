## Base/current-main RED receipt

Run both partitions at the recorded base SHA and retain their compact summaries and TRX files. The
receipt must record:

- exact checked-out SHA and commands;
- positive discovered and executed counts for each partition;
- each seeded-repository failure's typed message, including owner, probe classification, HEAD state,
  fixture-attempt identity, child identity, exit code, bounded output/error byte counts, and
  drain/timeout state;
- total Git probe receipts and the count with exit code zero plus zero required stdout bytes; and
- the result of the genuinely corrupt/missing repository controls.

RED is only a production-shaped seeded-repository fixture/publication or process/output-apparatus
failure with the retained typed evidence above. An unrelated test failure, a generic Git failure
without the receipt, or a discovery/build failure does not establish RED. If the recurrent event does
not reproduce, record the positive execution counts and outcome as an inconclusive negative-control
arm; do not invent a deleting actor or relabel the result as contention.
