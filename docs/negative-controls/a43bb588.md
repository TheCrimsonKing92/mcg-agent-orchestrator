### Two things this control establishes beyond "the test can fail"

**The decomposition separated the concerns rather than relocating them.** The mutation breaks exactly one of
the two methods. `FocusedRunner_BudgetExceeded_...` stays green under root-only termination because it no
longer asserts anything about the descendant — root-only still kills the child, which is all that test now
claims. Each method fails for its own reason and only its own reason. Had both gone red, the split would have
been cosmetic.

**The observed failure mechanism is deeper than the assertion that caught it.** The expectation on record was
that the descendant identity would report `running-same-identity` — an orphan left alive. What actually
happened is that the orphaned grandchild retained the inherited stdout/stderr pipes, so `$process.WaitForExit()`
in `Invoke-FocusedChildProcess` never returned and the harness hung until the 10-second failsafe fired. The
orphan wedges its own parent. That is the production hazard tree termination exists to prevent, and it is a
strictly stronger demonstration than the predicted one. The prediction in the paragraph above is left
unedited so the difference stays visible.

Note that the 10-second bound is a hang detector, not a timing assertion: GREEN completes in ~0.5s and RED
does not terminate at all, so lengthening the bound changes neither verdict. This satisfies rule (g) of
`test-design-discipline` and the lengthening test added in rule (m).
