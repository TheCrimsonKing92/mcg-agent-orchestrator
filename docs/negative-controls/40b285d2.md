# Production acceptance cohort negative controls

The Developer lane is restricted to `Invoke-WorkerBuildCheck.ps1`, so it cannot execute behavioral
tests or produce honest RED/GREEN receipts. The successful compile is not a substitute. Before
acceptance, a test-capable lane must apply each mutation independently, retain the focused RED TRX,
restore the exact source, and rerun the same selection GREEN.

- In `CohortAcceptanceStore.SaveGateReceipt`, remove the
  `HasAuthoritativeLandingEvidence` guard, and in `ConductorDriver.RunAcceptanceCohort` remove the
  cached-receipt invalidation branch. `Store_RejectsPassingReceiptWithoutAuthoritativeEvidence` and
  `CachedPassWithoutEvidence_InvalidatesBeforeLanding` must go RED, proving neither a new nor a
  legacy cached pass can authorize landing without exit-zero and normalized TRX facts.
- In `ConductorDriver.HasCoherentExecutedTrxEvidence`, restore
  `passed + failed <= executed`. Every row of
  `NonVerdictTrxOutcome_IsInfrastructureFailure` must go RED for Error, Aborted, Timeout, and an
  unknown outcome.
- In `GoalWorktrees.RemoveFailedMaterializationWorkspace`, remove only the
  `RecordAcceptanceCohortCleanupNeeded` call. `FailedMaterialization_CleanupFailurePersistsDebt`
  must go RED on the missing typed cleanup-debt record while retaining the simulated cleanup
  failure.
- In `ConductorBatchLoop.RunParallelAcceptanceBatch`, bypass selector incompatibility and invoke
  `RunAcceptanceCohort` for the first two Ready projections.
  `IncompatibleCohortCandidates_UseOrdinaryAcceptance` must go RED because the cohort override is
  reached; its two ordinary gate and landing assertions are the fallback controls.
- In `ConductorDriver.RunAcceptanceCohort`, remove the `AcquireCohortStableSlotLease` scope but
  keep the verifier call. `ProductionBatch_SelectsRunsPersistsLandsAndCleansOneSharedCohort` must
  go RED on `StableSlotLeaseObserved`, and `CohortStableSlotLease_RefusesToExceedTrustedHostGateCap`
  remains the independent capacity guard.
- In `ConductorBatchLoop.RunParallelAcceptanceBatch`, skip the production selector/coordinator
  block. `ProductionCohortRunsOneSharedGateAndBypassesOrdinaryMemberGates` must go RED on the cohort
  invocation and shared-receipt assertions while ordinary per-goal calls become visible.

Run the test-capable receipts with bounded filenames:

```powershell
dotnet test tests\Mcg.AgentOrchestrator.Infrastructure.Tests\Mcg.AgentOrchestrator.Infrastructure.Tests.csproj --no-build --filter 'FullyQualifiedName~AcceptanceCohortWorkflowTests|FullyQualifiedName~ConductorAcceptanceCohortTests' --logger 'trx;LogFileName=cohort-repair.trx' -v:minimal
dotnet test tests\Mcg.AgentOrchestrator.Infrastructure.Tests\Mcg.AgentOrchestrator.Infrastructure.Tests.csproj --no-build --filter 'FullyQualifiedName~ConductorBatchLoopTests|FullyQualifiedName~LandingExecutorTests' --logger 'trx;LogFileName=cohort-fallback.trx' -v:minimal
```

Record for every mutation: changed symbol, failing test name, exact assertion output, matched test
count, command exit code, and TRX path. Restore with a reverse patch (never reset the worktree), then
record the final current-HEAD GREEN receipts.
