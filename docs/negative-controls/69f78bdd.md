# Spec refinement intake negative controls

- RED: `GoalRefinementGate_records_distinct_countable_fallback_receipt` failed with
  `Assert.Single() Failure: The collection was empty` before production changes.
- GREEN: the same test passed after fallback provenance and stable receipt tokens were added.
- Ordering control: a blocking refiner does not run during goal creation or Researcher prompt
  preparation; Planner prompt preparation returns `SPEC_REFINEMENT_PENDING` without starting the
  refiner. A separately claimed durable outbox item owns the slow call, attaches the spec, and
  preserves the Researcher dispatch written while refinement was in flight.
- Recovery control: goal persistence and the unique `goal-spec-refinement:<goal-id>` work item are
  committed together; replay completes without another model call when the spec is already attached.
- Timeout control: a 25 ms injected subscription deadline produces
  `outcome=fallback reason_code=subscription-timeout` without launching a paid worker.
- Regression control: successful subscription output produces `outcome=completed` and preserves
  the parsed refined spec.
