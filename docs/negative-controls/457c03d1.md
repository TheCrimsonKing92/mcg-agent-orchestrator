# Negative controls: dashboard test-project extraction

Goal `457c03d1` moves the four dashboard test files out of
`Mcg.AgentOrchestrator.Infrastructure.Tests` without changing their behavior.

Operator authorization (verbatim): “All three authorized.”

That authorization binds the previously blocked implementation boundary:

- create a shared test-support project instead of moving shared helpers away from
  Infrastructure tests or duplicating them into Dashboard.Tests;
- update the three checked-in acceptance-manifest contract-test files atomically
  with the manifest; and
- coordinate against goal `732af577`'s manifest candidate, which is present through
  the current `main` integration before this implementation.

Retry authorization (verbatim): “Both authorized.” The completed move contains
the following four `src/` edits, recorded here so the operator can ratify or revert
the complete source-side boundary:

- `src/Mcg.AgentOrchestrator.Core/Application/RepositoryTestImpactPlanner.cs`
  implements the explicitly authorized routing of dashboard/API impact checks to
  the uniquely named `Mcg.AgentOrchestrator.Dashboard.Tests` project.
- `src/Mcg.AgentOrchestrator.App/Properties/AssemblyInfo.cs` implements the
  explicitly authorized `InternalsVisibleTo("Mcg.AgentOrchestrator.Dashboard.Tests")`
  registration. The same file also registers
  `InternalsVisibleTo("Mcg.AgentOrchestrator.TestSupport")`: the authorized shared
  support project calls App's internal `OrchestratorWorkspace` directly so the
  extracted helper retains compile-time binding instead of reflection or a
  duplicate helper.
- `src/Mcg.AgentOrchestrator.Infrastructure/Properties/AssemblyInfo.cs` is the
  first additional source file beyond the two explicitly named changes. It grants
  Dashboard.Tests friend access because the required per-process
  `AssemblyTempRedirect` references Infrastructure's internal
  `IWorkerIntegrityLabeler`; without it, the sanctioned build reports CS0122.
- `src/Mcg.AgentOrchestrator.Infrastructure/Workspaces/GoalAcceptanceVerifier.cs`
  is the second additional source file. It registers Dashboard.Tests as an MTP
  project (rather than VSTest), maps Dashboard.Tests and TestSupport paths into
  focused-evidence project/dependency closure, accepts the dashboard project
  aliases, and preserves unattended HostIntegration exclusion. Without this
  registration, the acceptance/focused-evidence path cannot execute and classify
  the extracted projects correctly.

Operator ratification (verbatim): “Both additional source edits authorized.”

This ratifies the two files recorded above as additional —
`src/Mcg.AgentOrchestrator.Infrastructure/Properties/AssemblyInfo.cs` and
`src/Mcg.AgentOrchestrator.Infrastructure/Workspaces/GoalAcceptanceVerifier.cs` — as
in scope. Both are additive registration entries: a friend declaration, and new
predicates and map entries alongside the ones that already exist. No existing project's
behavior changes. Recording the gap and requesting ratification, rather than either
making the edits silently or stopping with the goal unfinishable, was the correct
handling and is why this authorization could be written precisely.

Explicitly still out of scope: restructuring `ResolveDotnetTestRunner` to derive the
runner from each project's own `UseMicrosoftTestingPlatformRunner` declaration instead
of a central name allowlist. That is filed as backlog `d3f7c359` and must land alone,
because `GoalAcceptanceVerifier` is gate code and cannot validate itself inside its own
goal's gate.

One correction recorded against the operator, since this file is the authorization
record and a false account of it would mislead the next round. A narrower ratification
covering only the `ResolveDotnetTestRunner` predicate was drafted and not sent. It
would have been wrong. Registering the runner alone, without the
`ReferencingProjectsByProject` entries, yields a build in which the dashboard check
correctly resolves to `mtp` and still selects zero dashboard tests, because that map
governs whether a source change routes to the project at all. The result would have
passed a runner assertion while reproducing the exact defect this goal exists to close.
Registration here spans roughly ten coupled sites in one file; partial registration is
silently wrong and is not distinguishable from complete registration by reading the
diff.

The negative controls remain: the shared project contains support but no test
methods; xUnit collection definitions remain assembly-local; the dashboard test
assembly uses the Infrastructure per-process temp-root bootstrap model; source
edits are limited to the routing, friend-access, and acceptance-registration seams
enumerated above and do not change product behavior; and acceptance, not the
subscription worker, executes the test host.
