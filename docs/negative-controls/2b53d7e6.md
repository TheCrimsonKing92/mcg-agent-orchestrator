# Dispatch scope ownership: Acceptance execution contract

Status: Developer authored the regressions and compiled the candidate. Behavioral execution,
the negative control, exact executed counts, independent implementation review and the full
gate remain Acceptance-owned. This document is a procedure, not a passing execution receipt.

## Source-level pre-fix causal trace

`WorkerProfileDispatcher.PrepareTask` calls `WorkerBuildScopeDispatchPreparation.Prepare` before
dispatch recording. `BackgroundDispatchRunner.TryStartLatestDispatch` then calls
`RecordDispatchBaseCommit` before the `BeforeProcessStart` checkpoint. A typed checkpoint
conflict can therefore reject the start after the successor has replaced the scope file.
`DispatchRecordWriteException.PreservesAuthoritativeState` preserves the earlier durable state.
No contention mechanism or historical actor is inferred.

Previously `CompletionBuildDispatchReconciliationPolicy.Resolve` supplied the predecessor's
full captured digest to `OrchestratorBuildEvidenceCheck.Resolve`, which read the successor's
current file and rejected the unequal digest. Separately, `WorkerBuildReceipt.Evaluate` also
resolved the current file. A receipt's stable digest did not bypass the first rejection.

## Implemented authority and callers

- `WorkerBuildScopeDispatchPreparation.RecordDispatchBaseCommit` retains exact scope bytes
  and the existing dispatch-attempt timestamp at the spawn attribution boundary.
  Capture validates the actual goal/task, worktree, dispatch base and pinned baseline before
  recording; it does not resolve project selection or run a build.
  Provider session discovery can update the dispatch later, so that mutable session is not
  an ownership key (`RecordProviderSessionFromHeartbeat` / `TaskSpec.SetDispatchProviderSessionId`).
- `WorkerBuildScopeIdentity` adds nullable retained fields. `TaskSpec.SetDispatchBaseCommit`
  updates LastDispatch and DispatchHistory through `ReplaceLastDispatch`. Existing
  `TaskDispatchSnapshot` mappings and `SqliteOrchestratorStateRepository` JSON persistence
  carry the fields without a new store or schema migration.
- `BackgroundDispatchRunner` passes the current authoritative goal/task/dispatch to both
  `CompletionBuildDispatchReconciliationPolicy` and `WorkerDispatchCompletionClassifier`.
  Both the initial receipt evaluation and the pre-commit receipt recheck use that context.
- `WorkerBuildProjectScope.ResolveForDispatch` verifies the full captured digest and actual
  owner/attempt/base, then uses the same root/common-directory/branch/ancestry and required
  project selection as current-file resolution. It never writes the current scope file.
  `WorkerBuildReceipt.Evaluate` retains its full-or-stable receipt check, successful project
  execution checks and candidate tree digest check. Coverage remains enforced by the real
  completion consumer.
- Legacy two-field identities require the exact current bytes plus matching actual owner
  and baseline. Missing authority is explicit. No-scope/non-.NET completion remains available.
  Worker build selection, App completion-build production and MTP no-build reuse keep their
  current-file APIs; their validation has not been relaxed.
