the process id, one entry snapshot of all five test hooks, ordered probe events,
the selected branch, source, holder count, and classification.

The intentional overlap is an apparatus validation only. It proves that the
trace distinguishes an injected empty result from a probe timeout. It does not
prove that the historical acceptance failure had that cause: the proposed
cross-class neighbor ran in another test process, and the historical hook owner
was not recorded.

## Conditional ownership negative control

No complete-override ownership guard is added by this goal slice. Such a repair
is authorized only after a current-head stable-slot receipt identifies a
same-process hook leak as the cause.

If that prerequisite is met, acceptance must demonstrate the guard's authority:

1. With the complete immutable ownership guard removed or bypassed, a competing
   scope must be able to replace or partially clear the active state, or a stale
   scope must be able to restore out of order; the named control must be RED.
2. With the guard restored, the same operation must fail immediately with a
   deterministic diagnostic, the owner snapshot must remain intact, repeated
   disposal must be harmless, and exact prior state must be restored once; the
   control must be GREEN.

The Developer role is restricted to the sanctioned build check, so it cannot
produce either runtime receipt. Acceptance owns the focused matrix, RED/GREEN
negative-control execution if causally authorized, the complete `Dotnet build
slots` partition, and current-head TRX hashes.
