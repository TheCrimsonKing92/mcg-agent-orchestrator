## Ownership invariant and negative control

`OverrideTestHooksForTests` installs one immutable state containing all five
test-controlled paths and a unique owner token. `Attribute` reads that state
reference once. Installation, legacy mutation, and restoration share one narrow
gate; a competing scope or legacy setter fails immediately while an owner is
active. Owner-checked disposal restores the exact prior state once, and repeated
disposal is harmless.

`LockAttributionCompleteOverrideRejectsCompetingMutationAndRestoresPriorStateOnce`
is the barrier-controlled negative control. Its competing task attempts both a
partial legacy clear and a second complete scope while the owner is active. The
test requires deterministic diagnostics, verifies that the owner's complete
state remains visible, disposes twice, and checks that the exact prior delegate
and other prior values are restored. It then throws from a second scope body and
verifies that exception cleanup restores the same prior state.

Removing or bypassing either ownership check makes the control RED: the
competitor can mutate or replace the active state, so the expected rejection or
owner-state assertions fail. Removing owner-checked restoration likewise makes
the exact-prior-state assertions fail.

The Developer role is restricted to the sanctioned build check, so it cannot
produce either runtime receipt. Acceptance owns the focused matrix, RED/GREEN
negative-control execution if causally authorized, the complete `Dotnet build
slots` partition, and current-head TRX hashes.
