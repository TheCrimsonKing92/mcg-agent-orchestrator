## What the two directions establish that one could not

**The failure sets are disjoint.** Forcing the predicate false breaks only the natural-plan tests; forcing it
true breaks only the marker-only cases. Neither mutation breaks both.

A single-direction control proves a test is capable of failing. It does not prove the test is keyed on the
thing it claims to check — a test can fail for an incidental reason and still look controlled. Here the two
tests are pinned to **opposite edges of the same predicate**: one asserts substantive prose is admitted, the
other asserts degenerate prose is rejected. If `PlannerContract_MarkerOnlySectionBodies_Fail` were passing
incidentally rather than on lexical diversity, RED-B would have stayed green. It did not.

That is the direct exclusion of rule (l)'s "weakened assertion" and "unreached path" failure modes for this
pair, by construction rather than by inspection.

## Method note

An earlier attempt used the filter
`FullyQualifiedName~PlannerOutputContractTests|DisplayName~Natural...Retry` and matched **zero** tests
(exit 27). In `scripts/MtpTestRunner.psm1`, `FullyQualifiedName~` maps to `--filter-class` and `DisplayName~`
maps to `--filter-method`; tokens of the *same* type union, but mixing types intersects, which asked for a
test that is simultaneously in that class and named that method. Use one filter type per invocation. The
zero-test guard is what caught this rather than a silent empty pass.
