# Negative controls: provider production extraction

Goal `8fc5413a` extracts the provider configuration/runtime seam while preserving the
flat `Mcg.AgentOrchestrator.Infrastructure` namespace and every public API.

Production edits authorized by the validated planner, recorded before implementation:

- `src/Mcg.AgentOrchestrator.Infrastructure.Providers/Mcg.AgentOrchestrator.Infrastructure.Providers.csproj`
  creates the owned assembly with Core as its only project dependency.
- `src/Mcg.AgentOrchestrator.Infrastructure.Providers/ModelProviders.cs`,
  `OllamaDefaults.cs`, `ProviderSmokeTester.cs`, and `AgentCatalogStore.cs` physically
  move the four provider ownership units from the monolith. They retain their namespace
  and contents and are not linked or copied back into the old project.
- `src/Mcg.AgentOrchestrator.Infrastructure/Mcg.AgentOrchestrator.Infrastructure.csproj`
  references Providers because diagnostics and worker runtime consume the extracted API.
- `src/Mcg.AgentOrchestrator.App/Mcg.AgentOrchestrator.App.csproj` directly references
  Providers because App is the composition root and directly constructs provider types.
- `src/Mcg.AgentOrchestrator.Core/Application/RepositoryTestImpactPlanner.cs` and
  `RepositoryChangeClassifier.cs` classify the new production path as Infrastructure
  behavior and preserve conductor-relaunch/test selection semantics.
- `src/Mcg.AgentOrchestrator.Core/Application/RepositoryOwnershipMap.cs` classifies the
  extracted path as shared Infrastructure ownership.
- `src/Mcg.AgentOrchestrator.Infrastructure/Workspaces/GoalAcceptanceVerifier.cs` maps the
  new project into the typed changed-project/dependency-closure receipt and cache inputs.

Negative controls:

- the Providers project references Core only and never references the monolith, App,
  persistence, processes, workspaces, or workers;
- the monolith owns none of the moved files and no project uses linked/copied compilation;
- project references are acyclic and are discovered from project files by architecture
  tests instead of maintained as a project census;
- ProviderEnvironment tests retain explicit environment isolation and paid provider smoke
  remains opt-in; no worker dispatch or external provider request is started here;
- App build/run-directory packaging must contain exactly one Providers assembly; the
  single-file publish must contain the Providers assembly in its bundle manifest;
- acceptance owns test execution, aggregate discovery, publish, output-hash comparison,
  deterministic gate, and same-host post-extraction timing receipts.
