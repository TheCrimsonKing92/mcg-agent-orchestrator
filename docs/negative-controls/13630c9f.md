# Negative control: focused reuse avoids the generated test apphost

Goal: `13630c9f`

During the 2026-08-27 acceptance run, the operator observed a visible
`Mcg.AgentOrchestrator.Infrastructure.Tests.exe` `0xc0000142` dialog. A nested focused-test
apphost under `Temp\Low\...\focused-artifacts` ran in the same interval, but Windows did not
retain evidence that identifies the dialog owner by full path. The apphost association therefore
remains a strong hypothesis, not a proven attribution.

The RED arm changed the focused-runner happy-path test to require the executed command receipt to
name `dotnet` while production still launched `$reuse.ExecutablePath` directly.

- Command: popup-suppressed MTP run filtered to
  `FocusedRunner_Pass_ExecutesUnderLeaseAndWritesReceipt`.
- Result: 1 executed, 0 passed, 1 failed.
- Expected failure: `Assert.Equal() Failure: Strings differ`; expected `"dotnet"`, actual a
  generated apphost path under `C:\Users\miles\AppData\Local\Temp\Low\...`.
- Scope: this proves the test goes RED when focused reuse still selects the generated apphost. It
  does not claim to reproduce `0xc0000142`; the wrapper intentionally suppressed Windows error UI.

The GREEN arm changed focused reuse to execute `dotnet <validated test assembly>` and record the
complete command arguments. The apphost remains a required build-artifact invariant.

- Happy-path command receipt: 1 executed, 1 passed; the receipt identified `dotnet.exe`, placed the
  expected test assembly at argument zero, recorded exit code 0, and contained a nonempty TRX.
- Receipt/source ordering contract: 1 executed, 1 passed.
- Budget and exact-tree termination path: 1 executed, 1 passed in 16.2 seconds; no dialog appeared.
- Complete focused-runner class: 19 executed, 19 passed in 21.7 seconds.
- Source-size ratchets: 15 executed, 15 passed.

The budget test deliberately does not assert a readiness marker produced inside its timeout
window. `docs/test-design-discipline.md` records that exact assertion as a prior host-speed race;
execution authority instead comes from the separate happy-path receipt and TRX assertions.

This change does not alter the acceptance manifest's root command, which still names the generated
Windows `.exe` apphost. A later `Infrastructure.Tests.exe` dialog therefore would not falsify this
focused-runner change; it would eliminate focused reuse as the source and move diagnosis to the
manifest-launched gate process or another direct-apphost caller. Changing that root command also
invalidates partition reuse and belongs in a separately verified goal.
