## Spike a Claude Agent SDK worker harness for the Anthropic lane

Today the Anthropic worker lane shells out to `claude --model ... -p (Get-Content prompt)` and treats stdout as an opaque blob. `claude -p` buffers all output until completion, so the orchestrator cannot see progress (0 stdout looks identical to a hang - this caused a working worker to be cancelled at a 20-min wait cap on 2026-06-13), and the `WORKER_RESULT` contract plus the commit convention are prose the model may ignore (spark failed both ways; weak/cheap/local models fail this class consistently). The fix is to drive the inner loop through a harness we control instead of a buffered CLI. Key enabler (verified 2026-06-13 via the claude-api skill): the Claude Agent SDK resolves credentials the same way Claude Code does, including an `ant auth login` OAuth subscription profile - so an SDK-based harness keeps the subscription budget and does NOT force paid per-token API billing. Scope: behind the existing worker-profile abstraction (`WorkerProfileDispatcher`/`WorkerProfiles`), add an Agent-SDK-backed dispatch path for one Anthropic role first; capture changed files / commands / commit sha deterministically from SDK events rather than parsing a model-emitted block, stream progress events so stall detection keys on real activity (not stdout bytes - see [[worker-dispatch-monitoring]]), and enforce commit/verification as loop steps or tool gates. Keep codex/qwen on the wrapped-CLI path (no equivalent subscription-preserving SDK; codex removed its chat wire API per the decision record) and keep the outer orchestrator (decomposition, worktree isolation, acceptance gates, routing, recovery) unchanged. Before building, confirm the Agent SDK hook surface (PreToolUse/PostToolUse/Stop) and auth-profile usage against the Agent SDK docs - the claude-api skill reference covers the Messages API and Managed Agents, not the local SDK's hook names. Done when one role dispatches through the SDK harness on the subscription profile, the dispatch record is populated from structured SDK events (not WORKER_RESULT prose), progress/stall is judged from streamed activity, and a comparison run (same task via `claude -p` vs the SDK harness) shows equal-or-better acceptance plus richer per-dispatch signal for the outcome scorecard; tests cover event-to-dispatch-record mapping, enforced-commit, and stall classification. Managed Agents (server-hosted, paid per-token) is a deliberately deferred alternative for specific high-value runs, not the default given the subscription-first posture.
