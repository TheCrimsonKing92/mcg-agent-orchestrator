## Deepen acceptance verification beyond "tests pass" (semantic acceptance + prompt-injection gate)

The gates today prove a change is safe and committed (git-ground-truth, dirty/forbidden-path, provenance) and that the SUITE passes — but not that the change actually DID what the objective asked, and the chaos suite still lacks the prompt-injection-in-brief case it explicitly flags as untested. This is the highest-value bespoke surface (no off-the-shelf workflow engine verifies LLM output against intent). Add: (1) a semantic acceptance check that compares the landed diff/behavior against the goal's stated acceptance criteria (e.g. an LLM-judge over {objective, acceptance criteria, diff, test output} that must agree the criteria are met, recorded as a receipt — evidence-grounded, not narrative); (2) a ChaosGate for prompt-injection-in-brief (a worker brief containing adversarial instructions must not be able to exfiltrate, write outside scope, or bypass a gate — assert the scope/contract/change gates still catch the observable effect), with the anti-tautology companion. Done when: a goal whose tests pass but whose diff does NOT satisfy the stated criteria is blocked with a semantic-mismatch receipt; the injection ChaosGate fires and a weakened variant proves it non-trivial; ChaosGate/acceptance stay green. (Widen the moat — own what's specific to verifying an LLM.)

## A principled failure taxonomy that drives auto-recovery and routing

We keep hitting distinct dispatch failure modes — usage-limit lockout, build lock (CS2012), contract-format deviation, genuine code bug, provider/connectivity error, no-relevant-change, dirty worktree — and patch each ad hoc (`FailureTriagePlanner`/`GoalRecoveryPlanner` classify some, read-only). Promote this to a first-class failure-mode model: classify every recorded failure into a stable taxonomy from its evidence (exit code, output markers, git state, timing), and route each class deterministically — transient (limit/lock) → backoff+retry; format → soft-retry (already advisory); genuine → escalate with the failure class; provider → failover lane (RedelegateTask). The taxonomy feeds both auto-recovery (extend the `recover` command, commit `94633e1`) and the outcome scorecard/routing (avoid a model/lane that produces genuine failures, not transient ones). Done when: failures carry a taxonomy class derived from evidence; the conductor/recover path acts per class (retry vs failover vs escalate) instead of uniform retry; the scorecard distinguishes transient from genuine failures; tests cover each class's routing. (Unique to orchestrating an unreliable worker.)

Net: retire the rote per-dispatch char-threshold confirm; keep a circuit-breaker, but make it cost/anomaly-aware and policy-owned. Done when: a normally-sized Complex dispatch starts with no confirm flag; an over-budget dispatch is blocked/escalated by policy with a cost reason; an anomalously-bloated prompt (size disproportionate to complexity) is the only thing that still requires explicit operator acknowledgement; tests cover within-budget-start, budget-breach-block, and anomaly-breaker-fires-vs-legitimately-large-brief.
